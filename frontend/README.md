# 百闻录前端

Vue 3 + TypeScript + Vite + Vue Router。本地 SPA，读取已有 Java/MySQL 的真实统计，无模拟战绩，不在浏览器保存采集令牌。

## 本机运行

先启动项目后端（项目根目录）：

```powershell
powershell -File scripts/start-local-mysql.ps1
powershell -File scripts/start-backend.ps1
```

再进入 `frontend`：

```powershell
npm ci
npm run dev
```

访问 http://127.0.0.1:5173/ 。Vite 仅绑定本机，将 `/api` 代理到 `127.0.0.1:18080`。刷新按钮只读取已保存数据，不启动游戏采集。2026-10-13 已完成式神录名称顺序前 50 个式神、各前五名；前两个原先已保存的前十名记录保留，本批新增 260 条，连同原有书翁十条，共 270 条基线、51 个式神有观察。实际批次进度见 `data/live-capture/first50-S56-20261013/progress.json`。

## 页面

- `/#/`：总览、观察覆盖、式神列表、名称搜索、段位及样本筛选。
- `/#/shikigami`：已登记式神图鉴。
- `/#/shikigami/3`：书翁详情，含六段位统计、最近观察玩家分布、规则与排除信息。
- `/#/observations`：当前赛季近七天各式神快照数量、玩家数量与最近采集时间。
- `/#/method`：基线、样本推算、跨段位与统计边界说明。

目录现有 53 位式神，包括原有璇、追月神、书翁及本批次新增 50 位。页面覆盖数量以已上传的真实观察为准，登记目录不代表完成采集。没有有效变化区间时显示“—”，不显示假胜率或 0%。公开接口只提供聚合信息，不暴露玩家 ID、原图路径或数据库凭据。

生产静态文件输出到 `dist/`。本轮仅本地预览，尚未部署；后续由站点同域转发 `/api` 到 Java，不把采集令牌注入前端环境变量。

头像位于 `public/portraits`；背景与标志为项目绘制的装饰图形。追月神已改用[官网卡牌工具](https://ssr.163.com/cardmaker/#/)的原始彩色头像，官方卡牌编号为 `19700`（不要混用“追月神·水月”的 `61800`），原图 125×125，按璇、书翁约 1.2:1 的头部近景裁剪为 93×78，保留透明边角。官网原图比游戏截图少了界面边框和截图压缩，但仍是小尺寸素材，不冒充高清图。

璇与书翁保留现有已核对的游戏头像作为取景模板。2026-10-13 检查官网卡牌目录时未找到“璇”的同名条目，不能据此自动替换。书翁的官网编号 `11900` 已核对，并下载作参照，但其完整卡面并不适合直接充当头部近景。

后续优先从官网目录核对精确名称、官方编号和角色变体，保存原始图片到 `data/official-portraits/`，在配置中记录 `source_url` 和 `official_card_id`，再人工确定取景；网站使用本地保存的素材，不运行时依赖官网图片链接。官网未收录的角色继续保留已核对的彩色游戏截图，不能拿近似名字代替。

头像是独立的静态素材，不随战绩采集重复截取。新增素材先人工核对式神名称、彩色状态及裁剪位置，再登记到 `config/portraits.json`（坐标为原图像素，右/下边界不包含；`color_sample` 是裁剪后头像内部的区域，应避开彩色边框）。在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts/import-portraits.py --check
.\.venv\Scripts\python.exe scripts/import-portraits.py
```

导入会先检查全部图片的边界和内部色彩；疑似灰度素材拒绝整批导入，保留现有头像。低色彩角色可能需要人工复核，该检查不能代替身份核对。成功后生成带内容版本的头像地址，避免浏览器继续使用旧缓存。前端保留原图颜色，不通过减饱和度表示采集状态；状态由文字标签表示。
