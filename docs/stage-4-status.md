## 计算方式

对于两个相邻快照：

```text
胜场 = 结束累计胜场 - 开始累计胜场
积分差 = 结束百炼值 - 开始百炼值
推算负场 = (每胜加分 × 胜场 - 积分差) / 每负扣分的绝对值
汇总胜率 = 所有有效区间的胜场之和 / 所有有效区间的胜负场之和
```

分子必须非负且能整除。零胜且掉分可以推算全负；胜场和积分均不变不形成样本。累计胜场减少、不同计分组、跨赛季、未知段位、超出规则日期或积分下限、观察间隔过长均排除。五段和六段、七段和八段分别允许同组变化。

两端同组不能证明期间未跨组，也无法单靠积分排除额外奖励或保护机制。因此结果始终称为“百炼榜玩家样本推算”，不能宣称完整对局记录或全体玩家胜率。

窗口两端均包含，但不拆分跨窗口边界的区间；规则生效区间采用 `[effective_from, effective_to)`，结束观察恰落在规则截止点的区间也保守排除。窗口内其他赛季的观察仍是边界，不能筛掉后跨过去连接。

汇总计数溢出时，整份式神汇总返回 `COUNTER_OVERFLOW`，清空可发布计数/比例，保留内部区间计算依据，不发布部分累加结果。样本不足时保留胜负场和实际时间，公开 API 的胜率为 null；数据库生成列仍按非零计数生成数学比例，不应绕过 API 直接展示。

## 赛季折算

```text
P <= 1000：P
1000 < P <= 3000：1000 + (P - 1000) × 0.4
P > 3000：1800 + (P - 3000) × 0.2
```

`SeasonResetCalculator.reset()` 返回精确的 `exactPoints` 和向下取整后的 `resetPoints`。例如 3001 精确值 1800.2，最终值 1800。累计式神胜场跨季不重置；跨季积分和段位仍会变化，因此不直接差分。该函数只做用户规则的数学折算，不自动重置数据库、生成赛季初快照、确定段位或跨赛季推算胜负。

## 配置和重算

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| BWP_RULES_RESOURCE | classpath:rules/score-rules.yaml | 打包规则，或 `file:F:/.../confirmed-rules.yaml` |
| BWP_STATS_SEASON | S56 | 明确的目标赛季标识 |
| BWP_STATS_WINDOW | P7D | 最近七天，开发默认值；最多 366 天 |
| BWP_STATS_MAX_INTERVAL | PT24H | 相邻观察最大间隔，开发默认值 |
| BWP_STATS_MIN_GAMES | 1 | 发布推算比例所需最小场数，开发默认值 |

这些窗口、间隔和样本量默认值不是已经验证的业务门槛。后续试采后调整。

在 `confirmed` 模式下，规则文件确认前须补齐 `scope_key`、`season_keys`、`min_points`、带引号的 UTC `effective_from`，核对其他加扣分条件后才将 `conditions_confirmed` 设为 true。未知日期不能随意填入。`effective_to` 可为空，表示已确认起点后的开放有效期。字段拼写错误、重复 YAML 键、重复段位、错误正负号和整数类型在启动时拒绝。

用户明确要求的 `observation` 模式允许先按已有系数推算，仍要求范围、赛季和采用起点。未知积分下限保留为空，不把未知条件标成已确认；若配置积分下限则仍检查。

当前一次运行使用一个不可变规则版本。修改配置需要重启；使用外部规则文件无需重新打包，修改项目内默认文件则需要重新打包。保留旧规则文件，跨版本区间暂不拼接计算。规则版本覆盖不了的区间会被排除，不能把当前系数套用到所有历史记录。

首版按需完整重算一个式神的窗口数据，榜单查询在一个事务内按 ID 顺序锁定和更新全部式神。这样无需额外缓存表，也能立即反映窗口、补传和修正。代价是统计 GET 请求会更新派生汇总、扫描窗口快照并短暂占用行锁；当前适合本机小规模验证。数据量和访问量增长后，再改为按变更合并任务和定时刷新，不应直接按此方案承诺公网高并发。

管理修正、删除和手动重算 HTTP 接口仍留在第 7 阶段，未借用采集令牌开放管理权限。统计引擎已返回带前后快照 ID、规则版本和排除原因的内部 Trace，供后续核对页面接入。当前集成测试通过直接修改隔离测试库，验证修正和删除之后的重算。

## 查询接口

- `GET /api/health`：stage 为 4。
- `GET /api/rankings`：按可展示推算胜率从高到低返回，空胜率在后；同率保持式神 ID 顺序。
- `GET /api/shikigami/{id}/statistics`：指定式神；不存在返回 404。
- `GET /api/shikigami`：按式神 ID 返回目录，附同样的统计说明字段。

每项包含字符串形式的 `id`、`sample_wins`、`sample_losses`、`sample_games`、`contributing_players`、`win_rate`，以及 `status`、`period_start`、`period_end`、`stats_updated_at`、`window_start`、`window_end`、`scope_key`、`season_key`、`rule_version`、`rule_sha256`、`minimum_games`、`max_interval_seconds`、`excluded_intervals` 和推算说明。时间为 UTC，空比例和空时间使用 JSON null。

常见状态：`SEASON_UNCONFIRMED`、`RULES_UNCONFIRMED`、`NO_SAMPLES`、`INSUFFICIENT_SAMPLES`、`INFERRED`、`COUNTER_OVERFLOW`。排除原因计数只描述本次窗口内形成的候选区间，不代表被过滤的窗口外记录总数。
