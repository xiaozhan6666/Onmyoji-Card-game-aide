# S56：从当前观察起算，按段位汇总

2026-10-13 用户补充确认：当前 S56、游戏单服；式神累计胜场在赛季更新时不重置；赛季积分折算的小数向下取整。

## 统计起点

首次完整真实采集只保存每个玩家的基线，不计入任何历史胜场。第二次及以后，比较同一式神、同一玩家的相邻记录，用新增胜场与积分变化推算负场。因此赛季中期可以开始统计，不需要补齐赛季初数据，也不能称为整季胜率。

当前仍使用最近 7 天的默认展示窗口，起点以前的历史区间不计算；后续可用 `BWP_STATS_WINDOW` 调整。累计胜场虽然不重置，跨赛季仍有积分折算和段位重置，所以不直接差分，新赛季重新建立观察基线。

## 段位归属

每个式神返回五段、六段、七段、八段、名士、大名士六项统计，包含胜负场、总场数、参与玩家数、胜率、有效区间数和样本起止时间。

- 两端段位相同：假设期间未变段，将有效区间计入该段位。
- 五段与六段、七段与八段之间变化：系数相同，可计入式神总样本，但无法拆分各段位对局，单列为“跨段位未分配”。
- 不同计分组之间变化：排除该区间。
- 必须先建立完整相邻时间线再归属段位，不能先按段位筛掉中间记录，再跨过去连接。
- 各段位分别按总胜场除以总场数加权汇总。无样本胜率为 null；有全负样本为 `0.000000`。最小样本量对每个段位单独判断。
- 六个段位胜负场之和加未分配项等于总样本；同一玩家可贡献多个段位，因此段位玩家数不能直接相加。

不增加数据库字段或表，按段位的结果从快照计算；式神表仍只保存总汇总。

## S56 配置

`config/score-rules.yaml` 已设置 `calculation_mode: observation`、`season_keys: [S56]`，应用默认统计赛季为 S56，区分大小写。

`effective_from: '2026-10-13T05:31:38Z'` 是项目采用观察规则的起点（北京时间 13:31:38），不是 S56 开始日期或官方规则生效日期。此前区间不套用这套观察规则。

`scope_key: local-development` 沿用现有本地数据库的固定范围标识，当前用途为单服百炼榜，不代表另一个游戏区服。换其他模式/榜单范围仍需明确迁移或独立数据库，不能混用。

用户明确要求先观察，所以新增 `observation` 模式，按已有系数推算；`conditions_confirmed: false` 仍如实记录特殊计分条件未逐项核实，未知积分下限继续为 null，不擅自写成 0。若配置了积分下限，此模式仍遵守。结果明确为样本推算，不是精确对局记录。

省略 `calculation_mode` 时仍采用 `confirmed` 模式，只有适用条件完整且已确认才计算。观察模式同样要求范围、赛季和起点，拒绝未知模式和缺少这些边界的配置。上版规则归档在 `config/rule-history/score-rules-2026-10-12.yaml`。

## 折算和接口

`SeasonResetCalculator.reset()` 返回取整前的 `exactPoints` 和向下取整后的 `resetPoints`。例如 3004 → 1800.8 → 1800；3200 → 1840。

`/api/rankings`、`/api/shikigami`、`/api/shikigami/{id}/statistics` 增加：

| 字段 | 含义 |
| --- | --- |
| calculation_mode | observation / confirmed |
| conditions_confirmed | 特殊计分适用条件是否已逐项确认 |
| observation_start | 本版规则采用起点 |
| grade_statistics | 六个段位的统计列表，按 5–10 排列 |
| unassigned_grade | 可推算但无法分配段位的有效区间汇总 |

各段位包含 `grade`、`grade_name`、`status`、`sample_wins`、`sample_losses`、`sample_games`、`contributing_players`、`interval_count`、`win_rate`、`period_start`、`period_end`。grade 是整数，未分配项为 null；计数和胜率使用字符串。既有总汇总字段保留。当前没有完整真实快照时，总体及六个段位状态均为 `NO_SAMPLES`。
