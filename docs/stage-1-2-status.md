# 第 1、2 阶段开发记录

日期：2026-10-13。

## 已实现

- Python 3.12 独立虚拟环境、可安装包及命令行入口。
- 样本、OCR 配置、上传候选的 JSON Schema；字段命名与 MySQL 设计保持一致。
- 原图保存、SHA-256 校验、UTC 毫秒时间、首次落盘生成并保留 UUIDv7。
- 可配置的逐行逐字段像素框、坐标网格、裁剪原图与预处理图。
- PaddleOCR 3.3.2 + PaddlePaddle 3.2.2 CPU 推理，PP-OCRv5 mobile 检测/识别模型。
- 玩家 ID、段位、百炼值和累计胜场解析；低置信度、缺失、多框、过期资料及重复玩家进入待核对。
- 每次运行独立保存结果、区域标记图和诊断信息；支持重跑及对照人工标注评估。
- synthetic 和 replay 数据不会产生上传候选；程序尚无网络上传行为。

## 已验证

- 自动化测试：30 项通过，覆盖前导零、数值歧义和溢出、时区、重跑编号不变、资料过期、重复玩家及原图被修改等情况。
- `pip check`：依赖没有声明冲突，完整版本记录在 `requirements-lock.txt`。
- 真正执行 PaddleOCR 对合成图片识别：2 行 × 4 个字段，与人工编写的标准值全部一致。结果见 `data/demo-paddle-evaluation.json`。
- 以上 8 个字段只是模型与程序的冒烟验证，不代表真实游戏准确率，不作为第 2 阶段验收证据。

## 真实截图试测补充

用户提供 4 张榜单截图，含 1920×864 和 1280×576 两种尺寸，其中书翁同一页有两个版本。通过独立于上传流程的 `scripts/test_screenshots.py` 按图校准数字区域：前五名 40/40 个数字字段、20/20 行对应正确；底部自身记录另计 8/8 个字段正确。每张处理约 0.36–0.54 秒，不含加载，使用 2 线程。

本次验证了实际图片的积分与胜场 OCR；未验证玩家 ID、段位、自动身份关联或完整快照。原图没有可靠采集时间，未伪造该字段。测试结果和裁剪图保存在 `data/screenshots-test/run-20261013-122442/`。下一步使用新增截图作为独立验收集。
