## 执行与恢复

```powershell
.\.venv\Scripts\python.exe scripts/capture-first50.py --adb 'F:\Program Files\Netease\MuMu\nx_main\adb.exe' --serial 127.0.0.1:16384 --batch data/live-capture/first50-S56-20261013
```

只有本机已校准的 1920×1080 游戏界面适用。重复执行会跳过已上传式神，复用完整报告及原 outbox；失败的不完整采集保留证据并重新采集该式神。`--max-new 1` 可限制单次只新增一个式神。要在当前式神保存后停止，可创建批次目录下的 `stop.request` 文件；继续前删除该请求文件。

整个批次持有设备锁并复用一个 PaddleOCR 实例；运行期间防止系统自动休眠，结束释放。每项成功后立即保存本地回执。未知页面、资料冲突、低置信度业务字段或上传失败会停止并标记 needs_review，不凭空补数据。

式神身份由人工核对名称的式神录头像定位，再与排行榜头像中央图像作缩放匹配（selector ≥0.97，board ≥0.96），并逐行检查该式神标签及头像未变化。名称 OCR 留作辅助证据；单式神独立脚本未提供该参考时仍要求标题 OCR ≥0.95。玩家 ID、段位、积分与胜场要求没有放宽；资料双帧及返回榜单一致性检查保留。

仅对明确识别的玩家资料卡允许关闭恢复；同一式神重复选择偶尔导致空榜时，最多进行一次已核对式神的切走/切回。空榜不会作为数据上传。段位解析新增“初阶”形式；排除段位裁剪底部高度不超过 16 原图像素的装饰碎片，完整冲突文本仍拒绝。

榜单单行数字无法识别时允许识别整列，再按已验证的行中心定位；数字置信度仍须达到 0.95。昵称只作返回榜单的辅助核对，不能充当玩家 ID。昵称 OCR 不稳定时要求两次文字位置相同、有效文字图像非空、像素平均差不超过 2.5 且相关系数至少 0.99；文字位于裁剪边缘时仅限制额外留白，不放宽实际文字框范围。没有装饰头衔而偏低的昵称允许使用有界的扩展裁剪。失败的数值、资料身份或行关联仍会中止本次采集。

段位放大识别只有一个文本且置信度介于 0.85～0.95 时，可在同一裁剪上以原始尺寸重试一次；仅当完整文字（除空格）一致、原图置信度至少 0.95 时使用，并保留两种读取证据。资料页可能显示“八段五阶 5席”，按完整格式归入八段。

待复核现象：粉婆婆榜首在 `39-attempt-1` 显示“八段五阶5席”，重开资料后的 `39-attempt-2` 两帧均显示“大名士4席”，玩家 ID 相同。失败报告未上传，当前基线采用第二次实际截图；不能将这次差异解释为玩家短时间升段，也尚不能确定是资料缓存、刷新延迟还是其他游戏显示行为。后续应专门验证资料刷新稳定性，并在推算跨时间段位时继续保守排除不一致区间。
