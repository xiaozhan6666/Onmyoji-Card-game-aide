# 重点段位与式神场数变化

2026-10-13 更新，已应用到本机 MySQL 与前端。

## 段位展示

详情默认展示名士、大名士；五至八段放入默认收起的“其他段位”，有有效场数后展示。玩家分布也将其他段位收起，保留实际观察人数。总览及图鉴筛选将名士、大名士置前，其他段位保留在分组中。

不专门寻找低段位玩家，遇到的真实段位照常保存。`ranking_snapshot.grade` 仍支持 5～10，计分和跨段位判断不变。

## 表结构与场数口径

仍为两张业务表。通过 Flyway V3 增加式神表字段，不修改原 V1、V2 迁移。`shikigami` 现有 9 个字段，`ranking_snapshot` 仍为 10 个字段。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| id | INT UNSIGNED，自增主键 | 式神编号 |
| name | VARCHAR(64) | 精确名称，变体独立 |
| sample_wins | BIGINT UNSIGNED | 当前窗口内有效区间的新增胜场 |
| sample_losses | BIGINT UNSIGNED | 同一批有效区间的推算负场 |
| sample_games（新增） | BIGINT UNSIGNED，STORED 生成列 | 自动等于 sample_wins + sample_losses |
| win_rate | DECIMAL(9,6)，STORED 生成列 | 胜场 / 场数，零场时 NULL |
| period_start | DATETIME(3)，可空 | 有效区间最早起点，UTC |
| period_end | DATETIME(3)，可空 | 有效区间最晚终点，UTC |
| stats_updated_at | DATETIME(3)，可空 | 最近重算时间，UTC |

`sample_games` 是当前窗口（目前近 7 天）内有效区间的新增场数，不是生涯总场数，也不是相邻两次网页刷新的差值。单个区间由同一玩家、同一式神的相邻快照重新计算，因此不在快照表重复保存易失效的差值。

首次基线不计入场数，重复上传和刷新不累加。迟到数据、更正、窗口滚动可能令数值减少。MySQL 自动维护生成列，采集器不上传、Java 不单独写入，确保胜负与场数一致。最大允许胜负之和 18446744073709551614 可由 BIGINT UNSIGNED 容纳。

现有统计接口已提供 `sample_games` 十进制字符串，保持兼容；接口值由同一份有效区间报告计算。段位接口继续返回全部分组，前端只改变呈现方式。原始资料和图像不删除。

## 后续登场率

本次先保存场数基础，暂不发布登场率。各式神的榜单玩家、采集时间和有效区间覆盖不同，不能把尚无二次观察的式神当作零出场，更不能因此显示书翁登场率 100%。

后续需统一统计人群、榜单范围、时间窗口及覆盖要求，再确定分母：

- 某式神有效场数 / 所有纳入范围式神有效场数之和：最多称为“样本式神场数占比”。
- 某式神出场数 / 去重的玩家对局数：需要额外的对局身份或完整出场数据。现有快照不能识别同一局在多个式神中的重复，不能按固定倍数推得可靠分母。

名士、大名士分组应分别使用对应范围的分母，缺失样本不能当作零。该局限已写入网页统计说明。
